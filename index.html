What this is

gtm-ai-cli is a TypeScript command-line tool (gtm, alias zoominfo) that lets a logged-in ZoomInfo customer search, enrich, and act on go-to-market data from a terminal. It stores no data itself: every real command calls ZoomInfo's servers, mostly through ZoomInfo's MCP server, and for two command groups through the GTM REST API. This page is the onboarding hub for new engineers. Every fact on it was checked against the code at commit c6d4b7e; file paths are given so you can verify them.

Day one: get it running (≈15 minutes)

The unit suite mocks every network call, so you need no ZoomInfo account to build and test. Do not run gtm auth login or npm run test:live until you have a test login and permission to spend credits.

git clone https://github.com/zachstoia10/gtm-ai-cli.git
cd gtm-ai-cli
nvm install 24          # .nvmrc pins 24
npm ci                  # installs exactly what package-lock.json lists
npm test                # 16 files, 151 tests, ~1 s, all mocked
npm run typecheck       # tsc --noEmit
npm run build           # Bun bundles src/index.ts → dist/index.js (~0.44 MB)
node dist/index.js --help

Verified on Node 24.19.0: all 151 tests pass, typecheck is clean, the build writes dist/index.js. Use npx tsx src/index.ts <command> to run from source without building.

Five things to know before your first PR

Open PRs against the fork

This repo is a fork of Zoominfo/gtm-ai-cli. GitHub often defaults the PR base to upstream. Always target zachstoia10/gtm-ai-cli · main.

Logic goes in pure builders

Each command maps flags to request args in an exported buildXArgs function. That's what unit tests cover — keep network calls out of it.

Never start the release workflows

release.yml and semantic-release.yml use ZoomInfo's secrets and would try to publish @zoominfo/gtm-ai-cli and push to ZoomInfo's Homebrew tap.

Live tests spend real credits

GTM_LIVE_WRITES=1 mutates real data. Never point it at a customer account; never run the live suite in CI.

Conventional Commits matter

semantic-release picks the next version from feat: / fix: prefixes; docs(README): also cuts a patch release.

One request, step by step

Example: gtm companies search --name Acme -f table

  1. Startup — src/index.ts strips --debug, registers all groups, and Commander parses flags. A bad --format is rejected here (parseFormat in src/output.ts).
  2. Build args — buildCompaniesSearchArgs in src/commands/companies.ts maps flags to MCP argument names; helpers in src/utils.ts validate them.
  3. Call — mcpCall('search_companies', args) in src/mcp.ts.
  4. Session — withSession in src/credentials.ts supplies a valid token, refreshing it if needed.
  5. Unwrap — the MCP reply is turned into plain JSON (unwrap, tryParseJson).
  6. Print — print(data, 'table', select) in src/output.ts.
  7. Exit — beforeExit closes the MCP connection; errors become Error: … with exit code 1.

Shared by both: one login via withSession, the User-Agent: gtm-ai-cli/<version> header (src/pkg.ts), the debug logger (src/debug.ts), and the output formatter.

Login: gtm auth login

OAuth 2.0 + PKCE, so the CLI never needs a client secret. Code: src/commands/auth.ts → oauthLogin in src/oauth.ts.

1

Get a client ID

Reuse ~/.config/gtm-ai/client_id, or register a new public client at mcp.zoominfo.com/oauth/register (dynamic client registration, "DCR").

2

Open the browser

Create a PKCE verifier/challenge and a random state, start a callback server on localhost:9876, open mcp.zoominfo.com/oauth/authorize.

3

Receive the callback

Only GET /callback is answered; a mismatched state is rejected; the server gives up after 5 minutes.

4

Exchange and save

Swap the code for tokens at Okta, then saveOAuthCredentials writes credentials with expires_at = Date.now() + expires_in * 1000 — milliseconds, because expires_in arrives in seconds.

Every later command: withSession

Before the request
getValidCredentials refreshes first if the token expires within 60 s (TOKEN_EXPIRY_BUFFER_MS). No credentials → "Not logged in. Run: gtm auth login".
If the server rejects the token
The client throws SessionRejected on HTTP 401. withSession refreshes once and retries once. A second rejection → "Your session is no longer valid. Run: gtm auth login".
If refresh fails
Re-read the file: another gtm process may already have rotated the refresh token. If what it saved is newer and valid, use it; otherwise ask the user to log in.
Corrupt file
A missing or unparseable credentials file is treated as logged out.
logout / whoami
logout revokes both tokens at Okta and deletes credentials (keeps client_id). whoami decodes — but does not verify — the JWT access token.

History: the dropped * 1000

A recent change saved expires_at in seconds instead of milliseconds. Every command then looked expired and refreshed; with refresh-token rotation, parallel commands (e.g. bulk enrich via xargs -P) logged users out with invalid_grant. Fixed in commit 8673664 (PR #2). Three tests in src/credentials.test.ts guard it — "records a refreshed token as valid for its full lifetime", "does not refresh again on the next command after a refresh", and "keeps parallel commands logged in when the server rotates the refresh token". Keep them passing.

Flags that work almost everywhere

-f, --format
json (default), jsonl, csv, yaml, table. CSV prefixes cells starting with = + - @ with ' so spreadsheets don't run them as formulas.
--select a,b.c
Client-side projection of dotted paths, applied before formatting. Not the same as enrich's --fields, which asks the server for specific fields (requiredFields).
-d, --debug
Or GTM_DEBUG=1. Logs each MCP/REST call and response to stderr, truncated at 2,000 characters.
--file
Bulk enrich (up to 10 entries), dq inputs, audience rows, configs. Unknown keys in enrich files are rejected by normalizeEnrichEntries.

Look values up before searching

Search endpoints reject unknown industry, metro, or topic strings with 422. Users (and tests) should run gtm lookup --field industries --fuzzy software first; friendlyError in src/mcp.ts points at the right lookup field when this happens.

Add a subcommand that wraps an MCP tool

  1. Find the tool and its argument schema: gtm raw list-tools -f table (needs a login), or ask whoever owns the MCP server.
  2. In the right src/commands/<group>.ts, add an exported pure builder, e.g. buildFooArgs(opts), that maps flags to tool arguments and throws a clear Error for bad input. Use helpers from src/utils.ts.
  3. Register the subcommand inside registerX: flags, .option(...FORMAT_OPTION), .option(...SELECT_OPTION), and an action that does print(await mcpCall('tool_name', buildFooArgs(opts)), opts.format, opts.select).
  4. Add cases to src/commands/<group>.test.ts for the mapping and every validation error (see signals.test.ts).
  5. For a new group: create the file, export registerX, and add it to src/index.ts.
  6. Update README.md, .claude/skills/gtm-ai-cli/SKILL.md, and AGENTS.md if the command list changed; add a read-only case to src/live/read-only.live.test.ts.
  7. Run npm test && npm run typecheck && npm run build; commit as feat: ….

Multi-call commands

mcpCall calls process.exit(1) on a tool error, so a command that makes several calls can't catch a failure and continue. Plan for that, or change mcpCall to throw (and update callers).

Add a REST command

Same pattern, but call apiCall(path, { method, query, body }) from src/api.ts and use listQuery for list endpoints. Bodies are JSON:API documents (see buildPrepareBody in src/commands/data-quality.ts). Remember only 429 is retried — don't add retries that could double-send a POST; src/api.test.ts pins that.

Debug a user's failing command

  1. Rerun with --debug to see the exact tool name, arguments and response.
  2. 422 / "Invalid 'industries'" → the value isn't canonical; run gtm lookup --field … --fuzzy ….
  3. Try the same call through gtm raw call <tool> --args '{…}' to tell a CLI mapping bug from a server bug.
  4. "Not logged in" / "session is no longer valid" → check ~/.config/gtm-ai/credentials (expires_at should be a 13-digit millisecond timestamp). A clean slate: delete client_id and credentials, then gtm auth login.
  5. Login hangs or fails → something else is on port 9876.
  6. Reproduce as a unit test with mocked network before fixing; that's how PR #2 was proven.

Glossary

GTM
Go-to-market: the sales and marketing data (companies, contacts, buying signals) ZoomInfo sells.
MCP
Model Context Protocol: a standard for calling remote "tools". ZoomInfo's MCP server is the main backend; the CLI is an MCP client.
OAuth 2.0 + PKCE
Browser login for apps that can't keep a secret. The CLI proves it started the login by sending a hashed random verifier.
DCR
Dynamic client registration: the CLI registers itself once and saves the resulting client_id.
Refresh-token rotation
Each refresh returns a new refresh token and invalidates the old one — why parallel refreshes are dangerous.
JSON:API
The REST response format (data, attributes, errors) used by the GTM API; media type application/vnd.api+json.
Enrich
Given an identifier (domain, email, ID…), return the full ZoomInfo record.
Intent
Signals that a company is researching a topic, with a score (CLI filters like --signal-score-min) and audience strength.
Scoops
Real-time business events: funding, M&A, leadership moves, layoffs, launches.
Signals
Per-company bundle of latest intent, news and scoops (1–10 companies per call).
Engagements
Meetings and emails from the customer's connected systems; ask runs conversation-intelligence questions over them.
GTM Studio audiences
List-building workbooks of contacts or companies, with columns and rows the CLI can edit.
GTM context
The customer org's offerings, ideal customer profiles, personas and competitors.
Data Quality (dq)
REST features to prepare (normalize), segment, and score a customer's own records.
Exports
Send ZoomInfo records to a connected system such as a CRM; runs are asynchronous.
Credits
ZoomInfo's usage currency. Some operations spend them — another reason the live suite is opt-in.
Builder function
An exported pure buildXArgs that maps flags to request arguments; the unit of unit testing here.
SessionRejected
Internal error a client throws on HTTP 401 so withSession can refresh and retry once.

FAQ

Do I need a ZoomInfo account to work on this?

Not for most work. Build, typecheck and all 151 unit tests run offline. You need a test login only to try real commands or run the live suite.

Why are there two ways to talk to ZoomInfo?

The MCP server doesn't expose Data Quality or Exports, so those two groups use the GTM REST API (src/api.ts). Both share one login through withSession.

What's the difference between --select and --fields?

--fields (enrich only) asks the server to return specific fields. --select trims the output on your machine after the response arrives.

A user says they keep getting logged out. Where do I look?

src/credentials.ts. Check expires_at is in milliseconds, then look at refreshCredentials' handling of parallel processes. The three regression tests from PR #2 describe the expected behavior.

There's no wrapper for the MCP tool I need.

Use gtm raw call <tool> --args '{…}' today; add a curated command (see "How-to recipes") if it's used often.

What is .claude/skills/gtm-ai-cli/SKILL.md?

Instructions that let AI coding agents use the CLI. Keep it in step with the README when commands change.

What does the "DEMO COPY" banner in the README mean?

This fork was used for demos. At c6d4b7e the banner still mentions an intentional bug; that bug (the token-expiry one) was fixed in PR #2, and main has since reworded the banner.
